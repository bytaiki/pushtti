# 開発計画と検証

[文書一覧へ戻る](README.md) · [製品仕様](specification.md)

GitHub連携から育成・保存・描画へ順につなぎ、実際のChromeで動作を確認する。育成ルールは製品仕様を参照。

## 最初に確かめる体験

まず「実際のGitHubへのコミットが餌となり、経験値へ反映され、Chromeを開き直しても残る」までを、小さな画面でつなぐ。

キャラの完成を待ってからGitHub連携を始めない。見た目だけ完成して、データ連携や育成の楽しさを後から検証する順序を避ける。

## 1. 拡張機能の基盤

### 行うこと

- TypeScript・React・WXTでChrome拡張機能の最小構成を作る。
- GitHubの対象ページを識別し、右下のボタンと開閉パネルを表示する。
- ページ側の処理と背景処理のメッセージを通す。
- 小さなRiveデータを使い、CLIからの出力が拡張機能内で再生できるかを早めに確認する。本格的な3段階の制作は後の工程に分ける。

### 完了条件

- 実際のChromeへローカルの拡張機能を読み込み、対象ページでパネルが開閉する。
- GitHub内のページ移動で、別リポジトリの状態を表示し続けない。
- パネルを閉じると通常のアニメーションが停止する。
- ローカルでの起動・ビルド手順を整備する。

## 2. GitHubとの実データ連携

### 行うこと

- 公開リポジトリの情報、ブランチ、コミット、スター数を取得する。
- ブランチ先端の識別番号を前回と比較し、変更があったブランチを優先して確認する。
- 同じリポジトリの複数タブをまとめ、取得結果を再利用する。
- 一覧を最後まで取得し、回数制限や中断が起きても、続きから再開できるようにする。
- 読み込み中・確認待ち・取得失敗と、正常に取得できた状態を区別する。
- Botやマージの判別、コミット日時の意味を、実際の応答と具体例で確認する。

### 完了条件

- 仮データだけでなく、実際のGitHubの応答を画面へ表示できる。
- 更新のたびに同じ全履歴を無条件で取り直さない。
- 全件の確認が終わっていない状態を「新しいコミットなし」と扱わない。
- ページを開いた時・表示中の定期更新・手動更新が、取得回数制限を尊重して動く。

## 3. 育成ルールと保存

### 行うこと

- 育成計算を、GitHub通信・画面・Riveから分離する。
- 日時順のコミット処理、重複除去、経験値、進化、体調、死亡、次世代を実装する。
- 育成状態と取得途中の情報をChrome内へ保存する。
- スターの増減、誕生前の活動、死亡後の活動の扱いを製品仕様に合わせる。

### 完了条件

- 実際の対象コミットが1回だけ経験値へ反映される。
- Chromeを開き直しても、経験値・世代・履歴・更新状況が残る。
- 留守中の履歴を日時順にたどり、途中で死亡した世代を後のコミットで復活させない。
- 保存に失敗した場合、保存できたように見せたり、既存の履歴を消したりしない。

## 4. キャラ・コメント・歴代の表示

### 行うこと

- Rive CLIで1系統・3段階を制作する。幼体のかわいさから、成体の凛々しさへ変化させる。
- 小さなパネル内でも進化段階・体調・色が見分けられるか確認する。
- 育成状態をWebランタイムへ渡し、姿・動き・表情を切り替える。
- 出来事に合うコメントを表示する。文面は、少し生意気でユーモアのある口調に揃える。
- 歴代の見た目を残す方式を検証し、採用した方式で保存・表示をつなぐ。

### 完了条件

- 経験値や体調の変更が、実際のキャラの見た目に反映される。
- パネルを開いた時と新しい出来事で反応し、再取得しただけでは同じ餌の反応を繰り返さない。
- 次世代を始めても、前の世代の情報と見た目を確認できる。
- Riveの画像出力とChrome上の表示の両方を確認する。

## 5. 一連の体験の確認

意味のあるルールのテストと、Chrome上での確認を組み合わせる。日数の経過は制御できる時刻で再現し、実際に30日待つ検証にはしない。

| 分類 | 確認すること |
| --- | --- |
| 誕生 | 閲覧だけでは生まれず、「育てる」で育成が始まる |
| 経験値・進化 | 製品仕様の進化閾値の直前・ちょうど・直後が正しい |
| 体調・死亡 | 寂しさ・弱り・死亡へ切り替わる時刻の境界が正しい |
| 重複 | 同じコミットを別ブランチ・再取得・複数タブから見ても1回だけ数える |
| 対象外 | Botや合流だけのコミットを除外する |
| スター | 初期値、増加、減少、戻りで、仕様どおりに経験値を加算する |
| 留守中 | 途中に死亡条件があれば、その後にコミットがあっても死亡を記録する |
| 次世代 | 過去の世代を上書きせず、新しい世代を始める |
| 通信・回数制限 | 失敗・取得途中・再開で、二重計上や誤った死亡確定をしない |
| 保存 | 再起動で状態を失わず、保存失敗を明示する |
| 見た目 | 進化・体調・固定色・歴代の姿が、計算結果と一致する |
| ページ移動 | 他のページやリポジトリへ移動しても、表示や処理が重複・混在しない |

## その後の開発

- 初版を試し、成長ペース・コメント・育てる楽しさを確かめる。
- 自分のリポジトリだけ育成できる制約を追加する際に、本人確認と所有者の範囲を設計する。
- 対戦、人数補正、複数系統などは、その時の目的と負担を比較して順序を決める。
